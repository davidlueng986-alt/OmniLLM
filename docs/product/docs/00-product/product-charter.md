# OmniLLM 產品憲章

## 1. 產品使命
OmniLLM 是一個統一的本地 LLM 引擎平台。它把模型取得、裝置相容性判斷、底層引擎選擇、推理生命週期、對外調用與可視化診斷整合成同一產品，使使用者不必先成為模型格式、量化、driver 或 native runtime 專家，仍能可靠地在 edge device 上使用本地模型。

## 2. 核心價值
### 2.1 低技術門檻自動架設
產品必須把複雜度吸收在系統內，而不是把 GGUF、AOT package、context、batch、thread、GPU driver 與記憶體包絡直接丟給一般使用者。自動化包括裝置偵測、候選模型解釋、模型取得、相容性評估、引擎／後端建議、保守參數、失敗降級與具體修復建議。

### 2.2 統一調用
產品必須提供一套穩定的 capability、request、event、error、Session、Job 與 lifecycle 語義。各引擎保留自身優勢，但差異透過 capability negotiation 與 engine-specific extension 表達，不以靜默忽略或偽裝成共同能力處理。

### 2.3 可視化監控
產品必須把「目前在做什麼、為何變慢、資源由誰占用、是否降級、是否安全、怎麼恢復」呈現成可採取行動的資訊。Dashboard 的目的不是展示更多數字，而是降低操作與診斷成本。

## 3. 目標使用者
- **本機使用者**：希望在自己的裝置上下載或匯入模型，快速開始對話或其他推理，不需操作命令列。
- **Local Edge AI 開發者**：需要一致的 HTTP／AIDL 介面、token、模型能力與診斷資訊，以較低成本整合到 App、工具或工作流程。
- **研究者與工程師**：需要比較引擎、模型、量化、後端與裝置；保存可重現的 measurement profile；辨識性能與相容性差異。
- **維護者與平台整合者**：需要可局部演進的文件、穩定的核心不變式，以及明確的引擎 qualification boundary。

## 4. 產品承諾
1. 本地優先：prompt、模型與推理預設留在裝置內；任何網路能力都必須由使用者明確啟用。
2. 不假裝支援：不支援的 capability 以結構化方式拒絕或提供明示降級，不靜默改變語義。
3. 安全宣稱與機制一致：崩潰隔離、權限隔離、來源真實性與相容性證據不得混用。
4. 資源可預期：在可觀測與可控制範圍內，所有高成本動作先規劃、再准入、後提交。
5. 故障可恢復：回覆遺失、進程死亡、client disconnect、取消與儲存中斷具有明確狀態與對帳方式。
6. 可擴充而不失真：加入新引擎、新模型格式、新 transport 或新平台時，不破壞既有 canonical semantics。

## 5. 產品邊界
OmniLLM 聚焦於本地／edge 推理平台，不以雲端帳號體系、模型訓練、微調服務、跨裝置分散式推理或通用作業系統級 AI daemon 為核心。產品可連接網路取得模型、目錄、撤銷資訊或提供使用者啟用的 LAN 服務，但推理價值不依賴雲端。

## 6. 成功的產品狀態
一個成功的 OmniLLM 應讓新使用者能看懂裝置能力、取得合適模型並完成第一次推理；讓開發者能以一致介面接入並理解 capability 差異；讓研究者能追溯測量條件；讓維護者能在不改寫核心架構的前提下加入新引擎或新功能。

## 7. 設計驗收
- 三項核心價值都能追到至少一組使用者旅程、核心 capability、資料狀態與可觀測性。
- 任一功能都能說明對哪項核心價值有貢獻；沒有貢獻者必須被視為工具性依賴或重新評估。
- 任一安全文案都能追到實際隔離機制；任一性能宣稱都能追到 measurement profile 或標示為估計。
- 加入第六個引擎或另一個 client transport 時，核心產品語義仍成立。
