# ADR-002 — Plan → Reservation → Commit → Execute

## Context
高成本／有副作用操作必須在 resource admission 前可估算，且 commit point 可識別。

## Decision
Plan → Reservation → Commit → Execute。

## Alternatives considered
- 直接呼叫 engine 再觀測用量
- 單一 load/generate 方法內隱式准入

## Consequences
- API 較多但可測試 fault boundary
- 每個 plan 必須綁 owner/input/expiry

## Security／Resource／Compatibility
- 受影響的 trust、resource、identity、state 或 wire semantics 必須由 authority catalog 表達；adapter 不得建立私有例外。
- 變更若改 public／persistence／security major semantics，需 protocol/schema major version。

## Validation
- Repository validator 確認 authority／reference 無漂移；
- 對應 quality/security scenario 在實作期產生 evidence；
- Fault／negative test 必須覆蓋本決策要解決的失敗邊界。

## Reopen triggers
- engine 無法提供保守 envelope
- transaction model 需要主版本更新
